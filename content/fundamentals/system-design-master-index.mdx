## What this curriculum is

This is not a list of technologies to memorize. It is a **first-principles operating system** for designing unfamiliar large-scale systems in Staff/Principal interviews at FAANG and FinTech companies.

```text
Requirements → Scale → API → Data → LLD → HLD
→ Database → Partition → Cache → Messaging
→ Consistency → Failure → Security → Observability
→ DR → Multi-region → Cost → Trade-offs → Defense
```

## The only framework you need in the room

```text
1. Clarify (functional + non-functional + scope)
2. Estimate (QPS, storage, read/write)
3. Contract (API + data model)
4. Naive design (find the bottleneck)
5. Evolve (cache, partition, async, replicate)
6. Deep dive (hardest 20%)
7. Failures (timeouts, retries, fencing, DLQ)
8. Trade-offs (say what you rejected)
9. Close (10× scale + monitoring)
```

## Remember This

1. Access patterns choose databases — logos do not.
2. Every network call can fail; design the failure first.
3. Cache is easy; invalidation is hard.
4. Kafka partition = scale unit + ordering boundary.
5. Staff answers defend trade-offs under blast radius and cost.
