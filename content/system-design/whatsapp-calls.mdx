## 1:1 audio / video

<Mermaid chart={`sequenceDiagram
    participant A as Caller
    participant SIG as Call Signalling
    participant B as Receiver
    participant STUN as STUN
    participant TURN as TURN

    A->>SIG: call offer (SDP)
    SIG->>B: ring (WS / push)
    B->>SIG: answer (SDP)
    A->>STUN: ICE candidates
    B->>STUN: ICE candidates
    alt direct path fails
      A->>TURN: relay media
      B->>TURN: relay media
    end
    A<<->>B: WebRTC media
`} />

| Piece | Role |
|---|---|
| WebSocket signalling | Offer/answer, ICE, hangup |
| WebRTC | Actual audio/video |
| STUN | Discover public ICE |
| TURN | Relay when NAT blocks P2P |

**Why not Kafka for media:** latency + throughput wrong tool.

| Topology | Idea | Scale |
|---|---|---|
| Mesh | Everyone sends to everyone | Tiny calls only |
| MCU | Server mixes into one stream | CPU heavy |
| **SFU** | Server forwards selected streams | Preferred |

## Call corner cases

| Case | Handling |
|---|---|
| Network switch WiFi→LTE | ICE restart |
| Caller drop | Signalling hangup; timeout |
| Receiver never answers | Ring timeout → missed call event |
| TURN overload | Regional TURN pools |

---

## Interview explanation

> Messaging ≠ calling. Signalling rides WS; media is WebRTC. Group calls use SFU. STUN first, TURN fallback.
