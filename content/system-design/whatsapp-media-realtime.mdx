## Image / video / document

<Mermaid chart={`sequenceDiagram
    participant C as Client
    participant MS as Media Service
    participant S3 as Object Storage
    participant CDN as CDN
    participant Chat as Message Service
    participant R as Receiver

    C->>MS: request upload URL {mime, size, hash}
    MS->>S3: create object + pre-signed PUT
    MS-->>C: uploadUrl + mediaId
    C->>S3: PUT bytes (resumable)
    C->>Chat: send message {mediaId, thumb, caption}
    Chat->>Chat: persist metadata only
    R->>CDN: GET media via signed/CDN URL
`} />

| Rule | Why |
|---|---|
| No media in Kafka | Huge payloads, broker death |
| No blobs in Message DB | Cost + backup pain |
| Pre-signed URL | Upload bypasses app servers |
| Thumbnail | Fast list UI |
| Virus scan | Async worker on object create |
| Encryption | Client E2EE or server-side KMS |
| Expiration | Lifecycle policies |

## Live location

<Mermaid chart={`flowchart TD
  A[User A GPS] -->|throttled updates| LS[Location Service]
  LS --> R[(Redis TTL / stream)]
  LS --> WS[WebSocket to viewers]
  LS --> STOP[Stop / expiry timer]`} />

| Concern | Approach |
|---|---|
| Frequency | Adaptive; slow when static |
| Battery | Batch / significant change |
| TTL | Auto-stop after duration |
| Privacy | Only conversation members |
| Offline | Last point cached briefly; don’t spam DB |

## Typing indicator

<Mermaid chart={`flowchart LR
  A[Alice typing] -->|WS ephemeral| GW[WS Gateway]
  GW --> B[Bob devices]
  GW -.-> X[No durable DB write]`} />

| Concern | Approach |
|---|---|
| Debounce | Emit every 2–3s max |
| TTL | Auto clear after 3s silence |
| Rate limit | Drop under load |
| Multi-device | Fan-out to Bob’s devices only |

## Interview explanation

> Media uses pre-signed S3 + CDN; chat stores pointers. Typing/location are ephemeral realtime events. Kafka carries “media ready” events if needed — never the bytes.

## Corner case

Upload succeeds, chat send fails → client retries message with same mediaId (idempotent).
