## Multi-device

```text
One logical message
   ├─ deliver to phone WS
   ├─ deliver to desktop WS
   └─ unread sync across devices via serverSeq
```

Sender’s other devices also get an echo/sync event so all screens show the outbound message.

### Persist + publish

```java
@Transactional
public SendResult send(String userId, ChatFrame frame) {
    Optional<String> existing = idempotency.find(userId, frame.clientMsgId());
    if (existing.isPresent()) return SendResult.replay(existing.get());

    long seq = sequence.next(frame.conversationId()); // monotonic per conversation
    Message m = Message.create(frame, userId, seq);
    messageRepo.insert(m);
    idempotency.put(userId, frame.clientMsgId(), m.id());
    kafka.send("message.created", frame.conversationId(), MessageCreated.from(m));
    return SendResult.sent(m.id(), seq);
}
```

## Failure matrix

| Failure | Behavior |
|---|---|
| Sender disconnect after persist | Retry same clientMsgId → idempotent |
| Receiver disconnect mid-push | Pending remains; sync on reconnect |
| Delivery worker crash | Kafka redo; idempotent device delivery |
| Duplicate Kafka event | Delivery marked by messageId+deviceId unique |

---

## Interview explanation

> Client supplies clientMsgId. Server assigns messageId + serverSeq, persists, publishes. Delivery is multi-device aware. Status events close the tick loop.

## Corner case

Two devices ACK DELIVERED → first ACK flips status; later ACK is no-op.

## Scale

Message Service stateless; WS stateful; Kafka consumer groups scale with partitions.
