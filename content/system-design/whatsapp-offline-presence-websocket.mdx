## Presence

<Mermaid chart={`flowchart LR
  C[Client] -->|connect + heartbeat| WSG[WS Gateway]
  WSG --> PS[Presence Service]
  PS --> R[(Redis)]
  R --> M1["userId → {serverId, connIds[], lastSeen}"]
  R --> TTL[TTL refreshed by heartbeat]`} />

| Concern | Design |
|---|---|
| Heartbeat | Every 15–30s; refresh TTL |
| Disconnect | Explicit close or TTL expiry → offline |
| Multi-device | Set of connections; online if any alive |
| Last seen | Update on transition offline |
| Why not primary DB | Too hot; presence is ephemeral |

Redis Pub/Sub / streams optional to notify watchers of presence changes (privacy filtered).

### Presence failures

| Failure | Behavior |
|---|---|
| WS node death | TTLs expire; clients reconnect elsewhere |
| Redis blip | Treat uncertain; fallback push; rebuild on reconnect |
| Network partition | Client reconnect; authoritative presence = Redis after reconnect |

## WebSocket architecture

<Mermaid chart={`flowchart TB
  LB[Load Balancer] --> N1[WS Node 1]
  LB --> N2[WS Node 2]
  LB --> N3[WS Node 3]
  N1 --> R[(Redis connection registry)]
  N2 --> R
  N3 --> R
  DW[Delivery Worker] --> R
  DW -->|HTTP/gRPC push to node| N1
  DW --> N2
  DW --> N3
  N1 --> K[(Kafka optional for events)]`} />

| Topic | Recommendation |
|---|---|
| Sticky LB | Nice for reuse; **not sufficient alone** |
| Registry | `userId → [(nodeId, connId)]` in Redis |
| Node crash | Registry TTLs; clients reconnect; undelivered → sync API |
| Backpressure | Per-connection queues; drop typing first; never drop chat persist path |
| Heartbeat | Ping/pong; close zombie conns |

### Sticky vs non-sticky

```text
Sticky: same client prefers same node → fewer registry churns
Non-sticky OK if: every push looks up registry and calls owning node
```

## Interview explanation

> Presence is Redis+TTL. Offline means durable DB + push. WS fleet is horizontally scaled with a connection registry so any worker can find Bob’s node.

## Corner case

App killed without TCP FIN → wait TTL → brief “ghost online”; accept short lag or aggressive heartbeat.

## Scale

Autoscaling WS nodes on connection count; shard Redis; sync endpoints paginated by serverSeq.
