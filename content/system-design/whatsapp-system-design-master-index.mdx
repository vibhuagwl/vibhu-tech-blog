**Scope note:** This is an **industry-standard WhatsApp-like architecture** for Senior/Staff interviews — not a claim of WhatsApp’s private internals.

**Primary story:** *Alice sends Bob a message* → then expand to offline, group, media, typing, call.

```text
Alice → WebSocket → Gateway → Message Service → DB → Kafka
  → Presence → Bob WebSocket (or Push) → ACK → Read → Blue tick
```

---

## Interview answer lengths

### 5-minute answer

> Clients connect over WebSocket for realtime. HTTPS for login/history/media. Message Service validates, generates message ID, persists, publishes to Kafka partitioned by conversationId. Delivery workers check Redis presence: online → push on the right WebSocket node; offline → FCM/APNS and keep pending in Message DB. ACKs drive SENT/DELIVERED/READ. Media uses object storage + CDN, never Kafka. Calls use WebRTC with signalling over WebSocket. Scale with sharded message store, connection gateways, and Kafka partitions.

### 15-minute answer

Add: idempotency keys, ordering via conversation partition + server sequence, multi-device fan-out, group fan-out-on-write for small groups / hybrid for large, Redis for presence/session/idempotency/locks, Redis failure fallbacks, Kafka retries + DLQ, whiteboard architecture.

### 30-minute deep-dive

Add: WebSocket registry, sticky vs non-sticky, multi-region, E2E encryption impact at HLD, hot partitions, broadcast vs group, status TTL, payments webhook idempotency, observability SLOs, every “what if” failure.

## Whiteboard you must memorize

```text
CLIENTS (Mobile / Web / Linked Devices)
        |
   DNS / CDN / WAF → Load Balancer → API Gateway
        |
   AUTH | USER/GROUP | MESSAGE SERVICE
                          |
                     KAFKA CLUSTER
                          |
        DELIVERY WORKERS → WEBSOCKET GATEWAYS → Recipient
        NOTIFICATION → FCM/APNS
                          |
   REDIS (presence/session/idempotency/locks)
   MESSAGE DB (sharded) · OBJECT STORAGE → CDN
   OBSERVABILITY (metrics/logs/traces)
```

## Protocol cheat (say this early)

| Protocol | Use |
|---|---|
| HTTPS / REST | Login, profile, history, group admin, media metadata, search |
| WebSocket | Chat, typing, presence, ACK, group events |
| WebRTC | Audio/video media path |
| Kafka | **Internal** async pipeline only — not phone-to-phone |

> Kafka is **not** the direct channel between two mobile users.
