## 30-second story

> Alice sends Bob a message over WebSocket. Message Service validates, assigns ids, **persists**, then publishes to Kafka partitioned by `conversationId`. Delivery workers check Redis presence: online → push on the owning WebSocket node; offline → FCM/APNS and sync later. ACKs drive SENT / DELIVERED / READ. Media uses object storage + CDN. Calls use WebRTC. Kafka is internal — not phone-to-phone.

```text
Media → S3 → CDN
Calls → Signal(WS) + WebRTC
```

## Classic follow-ups

1. Ordering? → conversation partition + serverSeq  
2. Duplicates? → clientMsgId idempotency  
3. Offline? → durable DB + push + sync  
4. Scale connections? → WS fleet + registry  
5. Large groups? → hybrid fan-out  
6. Kafka down / Redis down? → see [failures Q&A](/system-design/whatsapp-interview-failures-cheatsheet)
