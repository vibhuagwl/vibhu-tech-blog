User pays → API saves critical state → Kafka → fraud / ledger / notify consumers. The API does **not** wait for every consumer.

## 20-second interview version

- Kafka decouples slow side effects from the user request  
- Partition key = ordering entity (`orderId`)  
- At-least-once ⇒ idempotent consumers  
- Watch consumer lag · poison messages go to DLQ  

## Remember

Partition = scale **and** ordering boundary.
