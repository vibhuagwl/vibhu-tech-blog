## Quick complexity ladder

| Name | Growth | Interview intuition |
|---|---|---|
| O(1) | Constant | Hash get (avg), array index |
| O(log n) | Logarithmic | Binary search, balanced BST height |
| O(n) | Linear | Single scan |
| O(n log n) | Linearithmic | Efficient comparison sorts |
| O(n²) | Quadratic | Nested loops over n |
| O(2ⁿ) | Exponential | Subsets / naive recursion |
| O(n!) | Factorial | Full permutations |

## How to answer in an interview

1. State **input size** (`n` = elements, `V`/`E` for graphs).
2. Give **time**: best / average / worst when they differ.
3. Give **extra space** (not counting input unless asked).
4. Name the **assumption** (e.g. hash uniform; tree balanced).
5. One sentence on **why** (loop structure / tree height / hash collisions).
