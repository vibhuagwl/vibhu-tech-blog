## Problem

Java `PriorityQueue` is a binary heap by default: the smallest element according to natural ordering or a comparator is at the root.

Let `N` be the number of elements.

| Operation | Expected heap action |
|---|---|
| `offer` / `add` | Insert at end, sift up |
| `peek` | Read root |
| `poll` | Remove root, move last to root, sift down |
| `remove(Object)` | Find object linearly, remove, restore heap |
| `contains(Object)` | Scan array |
| Heapify constructor | Build heap from existing collection |

## Heap height

### Problem

Operation costs depend on heap height.

### Java Code

```java
java.util.PriorityQueue<Integer> pq = new java.util.PriorityQueue<>();
pq.offer(10);
pq.offer(3);
pq.offer(7);
```

### Math

A binary heap is a complete binary tree stored in an array. With height `h`:

```text
maximum nodes up to height h = 1 + 2 + 4 + ... + 2^h
= 2^(h + 1) - 1
```

Solve for height:

```text
N <= 2^(h + 1) - 1
N + 1 <= 2^(h + 1)
log2(N + 1) <= h + 1
h = O(log N)
```

### Space

The heap stores elements in an internal array:

```text
input elements stored = O(N)
operation auxiliary space = O(1)
```

### Final

Binary heap height is `O(log N)`.

### Interview Explanation

"A heap is complete, so it stays shallow. The root-to-leaf path length is logarithmic in the number of elements."

## offer and add

### Problem

Insert a value into a Java `PriorityQueue`.

### Java Code

```java
static void insertExample(java.util.PriorityQueue<Integer> pq, int value) {
    pq.offer(value);
    pq.add(value + 1);
}
```

Conceptual heap insertion:

```java
static void siftUp(int[] heap, int index) {
    while (index > 0) {
        int parent = (index - 1) / 2;
        if (heap[parent] <= heap[index]) break;

        int temp = heap[parent];
        heap[parent] = heap[index];
        heap[index] = temp;
        index = parent;
    }
}
```

### Math

The new item starts at a leaf and can move up one level per loop:

```text
iterations <= heap height
height = O(log N)
work per iteration = O(1)
T(N) = O(log N)
```

Array resizing can occasionally copy `O(N)` elements, but amortized insertion remains `O(log N)` for normal use.

### Space

```text
auxiliary variables = O(1)
internal storage after insert = O(N)
```

### Final

`offer` and `add` are `O(log N)` time and `O(1)` auxiliary space, amortized aside from backing-array growth.

### Interview Explanation

"Insertion appends at the end to preserve completeness, then sifts up at most the heap height, which is logarithmic."

## peek

### Problem

Read the minimum element without removing it.

### Java Code

```java
static Integer readMin(java.util.PriorityQueue<Integer> pq) {
    return pq.peek();
}
```

### Math

The min element is stored at array index `0`:

```text
array read = O(1)
T(N) = O(1)
```

### Space

```text
S_aux = O(1)
```

### Final

`peek` is `O(1)` time and `O(1)` auxiliary space.

### Interview Explanation

"The heap invariant guarantees the priority element is at the root, so no traversal is needed."

## poll

### Problem

Remove and return the minimum element.

### Java Code

```java
static Integer removeMin(java.util.PriorityQueue<Integer> pq) {
    return pq.poll();
}
```

Conceptual heap removal:

```java
static void siftDown(int[] heap, int size, int index) {
    while (true) {
        int left = 2 * index + 1;
        int right = 2 * index + 2;
        int smallest = index;

        if (left < size && heap[left] < heap[smallest]) smallest = left;
        if (right < size && heap[right] < heap[smallest]) smallest = right;
        if (smallest == index) break;

        int temp = heap[index];
        heap[index] = heap[smallest];
        heap[smallest] = temp;
        index = smallest;
    }
}
```

### Math

`poll` removes the root, places the last element at root, and sifts down:

```text
levels moved <= heap height
height = O(log N)
constant comparisons per level
T(N) = O(log N)
```

### Space

```text
S_aux = O(1)
```

### Final

`poll` is `O(log N)` time and `O(1)` auxiliary space.

### Interview Explanation

"Removing the root may violate the heap invariant, so the replacement value moves down one level at a time. The number of levels is `log N`."

## contains and remove(Object)

### Problem

Find or remove an arbitrary object from a priority queue.

### Java Code

```java
static boolean hasValue(java.util.PriorityQueue<Integer> pq, int value) {
    return pq.contains(value);
}

static boolean removeValue(java.util.PriorityQueue<Integer> pq, int value) {
    return pq.remove(value);
}
```

### Math

The heap property orders only parent-child priority, not the entire array. There is no binary-search-like rule for arbitrary objects.

For `contains`:

```text
scan up to N array slots
T(N) = O(N)
```

For `remove(Object)`:

```text
find object = O(N)
restore heap after removal = O(log N)
T(N) = O(N) + O(log N)
T(N) = O(N)
```

### Space

```text
S_aux = O(1)
```

### Final

`contains` is `O(N)`. `remove(Object)` is `O(N)` because the linear search dominates.

### Interview Explanation

"A heap is not a sorted array. Only the root is globally best. Arbitrary lookup requires scanning."

## VERY IMPORTANT: why build-heap is O(N), not O(N log N)

### Problem

Building a heap by inserting `N` items one by one is `O(N log N)`, but Floyd's bottom-up heapify is `O(N)`.

### Java Code

```java
static void buildHeap(int[] heap) {
    for (int i = heap.length / 2 - 1; i >= 0; i--) {
        siftDown(heap, heap.length, i);
    }
}
```

Java's `PriorityQueue(Collection)` uses a heapify-style construction for the initial collection.

### Math

The mistaken derivation is:

```text
N nodes * O(log N) siftDown each = O(N log N)
```

That is an upper bound, but it is loose. Most nodes are near the bottom and cannot sift down very far.

Count by node height:

```text
nodes of height 0 <= N / 2
nodes of height 1 <= N / 4
nodes of height 2 <= N / 8
...
nodes of height h <= N / 2^(h + 1)
```

Total work is proportional to:

```text
sum over heights h of (nodes at height h * h)
<= N * sum h / 2^(h + 1)
```

The infinite series is constant:

```text
sum h / 2^h = 2
sum h / 2^(h + 1) = 1
```

Therefore:

```text
total build-heap work <= N * constant
T(N) = O(N)
```

### Space

Bottom-up heapify rearranges the existing array:

```text
S_aux = O(1)
```

### Final

Bottom-up build-heap is `O(N)` time, not `O(N log N)`. Repeated `offer` is `O(N log N)`.

### Interview Explanation

"The `O(N log N)` argument assumes every node can move `log N` levels. Leaves move zero levels, their parents move one, and only the root can move `log N`. Summing heights gives a linear total."

## Heap sort and k-largest patterns

### Problem

Heaps often appear inside algorithms, so derive the whole algorithm, not just one operation.

### Java Code

```java
static int kthLargest(int[] nums, int k) {
    java.util.PriorityQueue<Integer> minHeap = new java.util.PriorityQueue<>();

    for (int value : nums) {
        minHeap.offer(value);
        if (minHeap.size() > k) {
            minHeap.poll();
        }
    }

    return minHeap.peek();
}
```

### Math

The heap size is capped at `K`:

```text
N insertions into heap of size at most K = N * O(log K)
up to N polls from heap of size at most K = N * O(log K)
T(N, K) = O(N log K)
```

### Space

```text
heap stores at most K elements
S_aux = O(K)
```

### Final

Maintaining top `K` with a heap is `O(N log K)` time and `O(K)` space.

### Interview Explanation

"I use `log K`, not `log N`, because the heap never grows beyond `K` elements."

## Summary table

| Java `PriorityQueue` operation | Time | Auxiliary space | Why |
|---|---:|---:|---|
| `offer(e)` | `O(log N)` amortized | `O(1)` | Sift up height |
| `add(e)` | `O(log N)` amortized | `O(1)` | Same as offer, may throw on capacity in some queues |
| `peek()` | `O(1)` | `O(1)` | Root array read |
| `poll()` | `O(log N)` | `O(1)` | Sift down height |
| `contains(o)` | `O(N)` | `O(1)` | Linear scan |
| `remove(o)` | `O(N)` | `O(1)` | Linear scan dominates |
| Build from collection | `O(N)` | `O(N)` storage | Bottom-up heapify |
| Repeated insert build | `O(N log N)` | `O(N)` storage | `N` inserts |
