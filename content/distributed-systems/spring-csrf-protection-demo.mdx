## What this is

A **runnable** Spring Security lab at `spring-csrf-demo/` (:8090) that proves CSRF end-to-end:

| Path | Mode |
|---|---|
| `/transfer` | Session CSRF — hidden `_csrf` form field |
| `/spa/**` | Cookie CSRF — `XSRF-TOKEN` + `X-XSRF-TOKEN` |
| Forged POST without token | HTTP **403** |

Login: `alice` / `password`

## The problem in one sentence

If the browser **auto-attaches** a session cookie, an evil site can trigger a POST to your bank — unless you require a secret CSRF token the attacker cannot read.

## When to disable CSRF

| Credential style | CSRF |
|---|---|
| Session cookie (browser form) | **ON** |
| Cookie + SPA (JS reads token) | **ON** (`CookieCsrfTokenRepository`) |
| `Authorization: Bearer` JWT (no cookie session) | Usually **OFF** |

## Start here

1. Open **[source explorer](/spring-csrf-demo)**
2. `cd spring-csrf-demo && mvn test`
3. `mvn spring-boot:run` → http://localhost:8090
4. Try the forged POST button — expect 403

## Interview punchline

> CSRF protects cookie-authenticated browsers. Stateless Bearer JWT APIs typically disable CSRF because the browser does not auto-send the credential. CORS does not replace CSRF.
