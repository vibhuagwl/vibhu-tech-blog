## Live example (read this image first)

Two real browser tabs. Same victim. Different websites.

| Site | URL |
|---|---|
| Real bank (victim logged in) | `https://bank.example.com/login` → `/transfer` |
| Attacker page | `https://evil-gifts.example/win-prize.html` |
| Local demo (this repo) | `http://localhost:8090/transfer` |

![CSRF attack live example: bank.example.com session cookie, evil-gifts.example forged POST, HTTP 403 Invalid CSRF token, and Spring Security fix with hidden _csrf field](/images/spring-security/csrf-attack-live-example.svg)

### What the image shows

1. **Victim logs into** `https://bank.example.com` → browser stores `JSESSIONID`
2. **Victim opens** `https://evil-gifts.example/win-prize.html` → hidden form auto-POSTs to the bank
3. **Browser sends** the bank cookie automatically (attacker never sees it, but it is attached)
4. **Bank responds** `403 Forbidden` — `Invalid CSRF token` — transfer does **not** run
5. **Fix** — legitimate bank form includes secret `_csrf`; evil site cannot read it

## The forged request (exact shape)

```http
POST https://bank.example.com/transfer HTTP/1.1
Host: bank.example.com
Origin: https://evil-gifts.example
Referer: https://evil-gifts.example/win-prize.html
Cookie: JSESSIONID=A1B2C3D4
Content-Type: application/x-www-form-urlencoded

toAccount=ATTACKER&amount=9999
```

Missing: `_csrf=...`

That is the whole attack. The victim did not click Transfer on the bank site.

## Error you get when CSRF is ON

Spring Security `CsrfFilter` rejects the request **before** your controller runs.

| Field | Value |
|---|---|
| **HTTP status** | `403 Forbidden` |
| **Typical body** | `Invalid CSRF token found for https://bank.example.com/transfer` |
| **Filter** | `org.springframework.security.web.csrf.CsrfFilter` |
| **Side effect** | Balance / ledger **unchanged** |

In the local demo (`http://localhost:8090`), click **“Forge transfer without CSRF”** on the transfer page — same `403`.

MockMvc proof in the lab:

```java
mockMvc.perform(post("/transfer")
        .with(user("alice").roles("USER"))
        // .with(csrf())  ← intentionally omitted
        .param("toAccount", "B")
        .param("amount", "100"))
    .andExpect(status().isForbidden()); // 403
```

### If CSRF were wrongly disabled

| Field | Value |
|---|---|
| **HTTP status** | `302` (redirect) or `200` |
| **Side effect** | `Transferred ₹9999 → ATTACKER` written |
| **Why** | Cookie alone was treated as proof |

## How to fix it

### 1) Keep CSRF enabled for cookie/session browser apps

```java
http.csrf(Customizer.withDefaults());
// HttpSessionCsrfTokenRepository — token stored in session
```

### 2) Put the secret on the real bank form

```html
<form action="https://bank.example.com/transfer" method="POST">
  <input type="hidden" name="_csrf" value="8f3a…c91e"/>
  <input name="toAccount" value="B"/>
  <input name="amount" value="100"/>
  <button type="submit">Transfer</button>
</form>
```

Thymeleaf:

```html
<input type="hidden" th:name="${_csrf.parameterName}" th:value="${_csrf.token}"/>
```

### 3) Valid request succeeds

```http
POST /transfer
Cookie: JSESSIONID=A1B2C3D4
Body: toAccount=B&amount=100&_csrf=8f3a…c91e
```

→ `302 /transfer` (COMPLETED)

Evil site **cannot** read `_csrf` from `bank.example.com` (same-origin policy). Session cookie alone is no longer enough.

### SPA variant

Use `CookieCsrfTokenRepository` → JS reads `XSRF-TOKEN` cookie and sends header `X-XSRF-TOKEN`. Missing header → same **403**.

## When to disable CSRF

| Credential style | CSRF |
|---|---|
| Session cookie (browser form) | **ON** |
| Cookie + SPA | **ON** (`CookieCsrfTokenRepository`) |
| `Authorization: Bearer` JWT (no cookie session) | Usually **OFF** |

CORS does **not** replace CSRF. CORS stops JS from *reading* cross-origin responses; CSRF stops a foreign page from *triggering* cookie-authenticated writes.

## Interview punchline

> Attacker page at `evil-gifts.example` can force the browser to POST to `bank.example.com` with the victim’s `JSESSIONID`. With Spring CSRF on, the response is **403 Invalid CSRF token** and money does not move. Fix: require a secret `_csrf` only the real bank page can embed.
