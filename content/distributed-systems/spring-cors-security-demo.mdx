## What this is

A **runnable** end-to-end CORS lab:

| Piece | Origin |
|---|---|
| API (`spring-cors-demo`) | `http://localhost:8091` |
| Frontend (`frontend/`) | `http://localhost:5500` |

Same laptop, **different port** → cross-origin. Browser enforces CORS; Spring advertises the allowlist.

## The problem in one sentence

JS on origin A must not read responses from origin B unless B explicitly opts in with `Access-Control-Allow-Origin`.

## CORS vs CSRF vs Auth

| Control | Protects against |
|---|---|
| **CORS** | Hostile JS reading cross-origin responses |
| **CSRF** | Hostile site triggering cookie-authenticated writes |
| **Authn/Authz** | Who the caller is / what they may do |

## Start here

```bash
cd spring-cors-demo && mvn test && mvn spring-boot:run
# other terminal
cd spring-cors-demo/frontend && python3 -m http.server 5500
```

Open http://localhost:5500 — click Public / Me / Transfer.

## Interview punchline

> CORS is a browser policy, not authorization. Spring only echoes which origins may read responses. Never combine `Allow-Origin: *` with `Allow-Credentials: true`.
