## Business problem

Calculate tax using external tax services and business rules — asynchronously when external calls and workflows take time.

## Architecture

```text
Client
  → REST API
  → Tax Service
  → Camunda Workflow
  → Drools (rules / bands / rates)
  → External Tax API (GraphQL and/or REST — [NEEDS MY REAL PROJECT DETAIL])
  → S3 (payload/artifacts)
  → SQS (events)
  → Response Listener
  → Database + Async API Tracker
  → Final response / status
```

## Why this design
Long-running external dependency + rule engine + auditability → workflow + async tracker beats a single blocking HTTP call.

## Alternatives
- Fully sync REST to tax provider (timeouts, poor UX under load)
- Pure code if/else instead of Drools (harder for business rule churn)
- Only queues without workflow visibility (harder ops tracing)

## Failure highlights
- External tax timeout → retry policy / park workflow / timer
- Drools misrule → wrong calculation → need rule tests + audit
- Lost callback → tracker stays PENDING → reconciliation
- SQS redelivery → idempotent listener
