## Flow

```text
Input
  → Facts
  → Rules
  → Tax band / rate / decision
  → Calculation output
```

## Why Drools
Business rates/bands change more often than code deploy appetite; rules isolate decision logic and enable business-readable tests.

## Realistic example (illustrative)
Income/fact set → band rule matches → rate applied → tax amount. Replace with `[NEEDS MY REAL PROJECT DETAIL]` real rule categories you can discuss.

## Risks
Rule conflicts, silent priority bugs, undeclared fact fields — mitigate with rule unit tests and controlled deployment.
