## Business requirement

Onboard participants / create operational accounts so downstream cash/ops systems can process against a known entity.

## Flow

```text
Request
  → Authentication
  → Authorization
  → Validation
  → Participant creation
  → Operational account creation
  → Persistence
  → Event publishing
  → Downstream processing
  → Status update
```

## Idempotency

Client retries must not create duplicate participants. Use idempotency key / natural business key unique constraint.

## Failures
- Validation fail → 4xx, no side effects
- DB fail → no event
- Event fail after DB → dual-write problem (same as Cashlines)
- Downstream reject → status = FAILED / NEEDS_REVIEW with reason codes
