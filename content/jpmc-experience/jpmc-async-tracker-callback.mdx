## Tracker model (pattern)

```text
requestId
correlationId
transactionId
status
createdAt / updatedAt
request/response refs (S3 keys or payloads)
errorCode / errorMessage
retryCount
workflowInstanceId
```

## Flow

```text
Client → requestId → DB tracker → workflow/external
  → async event/callback → validate → update tracker → final status
```

## Callback risks
Duplicate callbacks · out-of-order · auth failure · timeout with late success → reconcile via tracker + external id.

## Support superpower
Give support one `requestId` / `correlationId` and reconstruct the journey across API, workflow, S3, SQS, Kafka.
