## Components to know cold

- `CommonErrorHandler` / `DefaultErrorHandler`
- `DeadLetterPublishingRecoverer`
- `FixedBackOff` / `ExponentialBackOff`
- Ack modes and when offsets commit
- Seek behavior after failures

## Lifecycle

```text
ConsumerRecord
  → listener
  → exception
  → DefaultErrorHandler
  → retry with backoff
  → recovery (DLQ publish)
  → offset can advance after recovery
```

## Spoken answers

**What happens to the offset when an exception occurs?**  
Depends on ack mode and whether the error handler recovers. With DefaultErrorHandler + recoverer, after retries the record is recovered (e.g. DLQ) and the consumer can move past it.

**Same message keeps failing?**  
Retry budget then DLQ. If misconfigured to retry forever, you block progress and inflate lag.

**Consumer restarts?**  
Resumes from last committed offsets; uncommitted work may redeliver → idempotency required.

**During rebalance?**  
Partitions revoked/assigned; in-flight processing must not assume exclusive ownership forever; commit carefully.
