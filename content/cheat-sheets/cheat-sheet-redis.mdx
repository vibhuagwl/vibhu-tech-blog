## Patterns

| Pattern | Note |
|---|---|
| Cache-aside | App owns read/fill |
| Write-through | Write cache+DB |
| Write-behind | Risk durability lies |
| TTL | Bound staleness |
| Negative cache | Protect misses |

## Dangers

Stampede, hot key, thundering herd, using Redis as unnoticed SoR, invalidation bugs.

## Failure line

> If Redis dies, protect the database and degrade deliberately.

## Remember

Cache is easy. Invalidation is hard.
